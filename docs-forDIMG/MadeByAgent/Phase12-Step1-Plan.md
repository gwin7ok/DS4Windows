## 4. 方針の項目と決める順序（依存関係の順）

1. **ログの出し先の分類**: 画面（GUI）／ファイル／トレイ通知の区別。`LogToGui(warning)` と各 `LogDebug` の命名のずれの扱い。
2. **レベルの基準**: Trace／Debug／Info／Warn／Error の定義と判定の問い（利用者に意味があるか、頻度、回復可能か）。高頻度経路（入力ループ）は Trace に限る、などの規則。
3. **GUI に出す基準**: 利用者向けの事象のみ。`temporary` の使い所。
4. **接頭辞の規則**: `[DI]` の扱い、機能名の接頭辞の整理、診断用の一時的な接頭辞（`[Diag-Toast]`）を恒久コードに残してよいか。
5. **文言の書式**: 言語（日本語・英語の混在。リソース化の要否は 4.2.3 の前例）、`key=value` の書式、例外の出し方。
6. **高頻度経路の規則**: `IsTraceEnabled`／`IsDebugEnabled` ガードの義務化の範囲。
7. **AppLogger 外の経路**: `Trace.WriteLine`／`Debug.WriteLine`／`Console.WriteLine` の扱い（AppLogger への統一か、L2 の判断に回すか）。
8. **API の整理方針（L2 向け）**: `warning` 引数の Info／Warn 別メソッド化、`TrayIconLog` の削除、private `LogDebug` の統一。
9. **テストでの扱い**: ログを期待値にするテストの方針（文言への依存を減らすか）。

## 5. 規約 §2.3 の改定案（1d）

現行: 既存のログ出力とレベルの完全な維持。案:

- 通常の Phase では、従来どおり文言とレベルを維持する。
- ログ整理の Phase（13b）に限り、`Log-Policy.md` に沿った変更を許可する。変更は「レベルのみ／文言／削除」に分けて記録し、利用者に見える GUI・トレイのログの変更は一覧で承認を得る（Phase8-Step8-Q7 の前例）。
- 新規のコードは、最初から `Log-Policy.md` に沿って書く。

## 6. 決定事項

計画書の承認時（2026-11-03）に決定済み:

- 項目 7（AppLogger 外の出力）は L1 の範囲に**含める**（方針まで決める。実施は L2）。
- 方針書の正本は `Log-Policy.md`。規約 §2.3 には要約だけ入れる。
- ブランチは `Phase12`（Phase11 の最終コミット 086651d0 から作成済み）。
- 1b は**全項目を 1 項目ずつ**質問する。

1b の各項目の決定（追記していく）:

- **項目 1（出し先の分類）＝ B: レベルを軸にする**（2026-11-03）。すべてのログにレベルを付ける。GUI への表示は、レベルと独立した「利用者向け」の印（引数）で決める。`LogDebug` が GUI に出る命名のずれは、この方針で解消する（実施は L2）。A（出し先を軸）は不採用。

- **項目 2（レベルの基準）＝ 頻度＋意味の基準**（2026-11-03）。5 段階を維持する。Trace＝毎フレーム・高頻度の経路追跡／Debug＝開発者向けの状態・分岐（低頻度）／Info＝利用者にも意味のある出来事（接続、プロファイル適用、起動・停止）／Warn＝異常だが継続できる（フォールバック、不正な入力）／Error＝処理の失敗（例外、機能不能）。判定の問いの細部は 1c の方針書で詳細化する。

- **項目 3（GUI に出す基準）＝ Info 以上＋印**（2026-11-03）。GUI 表示の候補は Info／Warn／Error のみ。そのうち「利用者向け」の印（引数）があるものだけ表示する。Trace／Debug は表示不可。一時表示（`temporary`）は印の変種として維持する。

- **項目 4（接頭辞）＝ [DI] 維持＋機能名で統一**（2026-11-03）。DI の境界を通過する重要操作は `[DI]` を付ける規約を維持する。それ以外は `[機能名]` の形に揃える。診断用の一時的な接頭辞（`[Diag-Toast]` など）は恒久コードに残さない。

- **項目 5（文言の言語と書式）＝ 英語に統一＋key=value**（2026-11-03）。ファイルログ・診断ログは英語。値は `key=value`、例外はメッセージ＋型名。利用者向け（GUI）の文言はリソース化して言語設定に従う（4.2.3 の前例）。

- **項目 6（高頻度経路のガード）＝ 文字列組立ありは必須**（2026-11-03）。Trace／Debug で、補間文字列・連結・割り当てを伴うログは `IsTraceEnabled`／`IsDebugEnabled` のガード必須。定数文字列のみなら不要。入力ループ（毎フレーム）は常にガードする。

- **項目 7（AppLogger 外の出力）＝ AppLogger に統一**（2026-11-03）。`Console.WriteLine`／`Debug.WriteLine` は廃止して AppLogger へ。NLog の直接呼び出しは、ログ基盤（`LoggerHolder` など）の内部に限り許可する。実施は L2。

- **項目 8（API の整理）＝ 汎用 `Log(level, message, options)` に統合**（2026-11-03。推奨［レベル別メソッド＋印引数］とは別の案をユーザーが選択）。`AppLogger` の入口を 1 メソッドに集約し、`options` で利用者向けの印・一時表示を指定する。各サービスの private `LogDebug` と `TrayIconLog` は廃止する。`LogToTray`（通知）の位置づけは 1c で詰める。L2 の変更量は最大になるため、1e で作業量を再見積りし、段階的な移行（旧 API を薄いシムとして残す期間）を検討する（規約 §2.1）。

- **項目 9（ログを期待値にするテスト）＝ レベルと主要語で検査**（2026-11-03）。文言の完全一致ではなく、レベルと `key=value` などの主要語を検査する。L2 で既存テストをその形に書き換える。
