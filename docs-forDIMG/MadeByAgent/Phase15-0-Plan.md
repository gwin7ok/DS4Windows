## 3. 守るもの

- ログのレベルと文言は、規約 §2.3 の例外（ログ整理の Phase）に当たる A でだけ変える。利用者に見える GUI・トレイの文言の変更は、**英語・日本語の一覧を作り、承認を得てから**行う（Phase8-Step8-Q7、Phase13b の前例）。ファイルだけに出るログの文言は変えない。
- テストの改名（B）では、テストの中身（入力・期待値）を変えない。過去の計画書・完了報告がテストのクラス名を根拠として引いているため、**旧名 → 新名の対応表**を残す。
- 規約 §3.4 R7（ファイルの移動は `git mv` だけのコミット、内容の書き換えは別のコミット）を守る。
- 安全弁（規約 §2.2）を守るテストは、名前を変えても検査の内容を変えない。

## 4. 進め方の原則

- 各 Step の終わりに Debug ALL（Benchmark を除く全件）。途中の確認は `Category!=Slow&Category!=Benchmark`。
- A は本体（`DS4Windows/`）を変えるので、最後に実機確認を 1 回行う（H5）。B〜D はテストだけ。

## 7. リスク

| リスク | 対策 |
|---|---|
| ログの文言をリソースへ移すときに、書式の引数の順番や数を取り違える | 書式の引数の数を、英語・日本語の両方でテストで照合する（リソースの値の `{0}`〜の数と、呼び出しの引数の数）。`AppLogger` の出力をそのまま比べる既存のテストを使う |
| 日本語の訳で、利用者に見える文言が変わる | 15-0-0 の一覧で承認を得る。承認していない文言は英語のまま |
| テストの改名で、過去の文書からテストをたどれなくなる | 旧名 → 新名の対応表を残し、計画書・完了報告から引けるようにする |
| 共有の状態の整理で、テストの前提が変わる | 状態を各テストで作り直すときは、期待値を変えない。並列は条件を満たさなければ有効にしない |
