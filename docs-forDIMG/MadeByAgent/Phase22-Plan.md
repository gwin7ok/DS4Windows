# Phase19 計画書: USB の Xbox 360 コントローラーを入力機種として足す

作成日: 2026-11-10
前提: `Xbox-Input-Research.md`（調査と実機の確認の結果）、`Phase18-Plan.md`（読み取りの骨組みと、機種を足す差し込み口の完成）、`Model-Diagram/02-Extension-Guide.md`（機種を足す手順）。
追加の調査は、各 Step の実施時に行う（本計画書では、調査済みの事実だけを前提にする）。

## 1. 目的と終わりの状態

- USB 接続の Xbox 360 コントローラー（Windows 上の名称「XBOX 360 Controller For Windows」。VID_045E、PID_028E）を、DS4Windows の入力機器として使えるようにする。仮想パッドへの出力と、マッピングは、既存の経路をそのまま使う。
- 機種は、単純な機種の最短経路（`IDeviceProtocol` ＋ `ProtocolDeviceCartridge`）で足す。ジャイロ・タッチパッドは持たない。
- ゲームに物理コントローラーを見せない（二重入力の防止）ために、HidHide で隠す。方式は §2 の決定 3 のとおり。
- 守るもの: 動作の完全維持（2.2）、ログの文言（2.3）、既存の機種（DS4・DualSense・Switch Pro）の動作。

## 2. 設計の決定

| 番号 | 項目 | 決定 | 理由 |
|---|---|---|---|
| 1 | 対象の範囲 | USB 接続の Xbox 360 系のみ。Xbox One／Series の USB と、Bluetooth の Xbox は、この Phase の対象外 | 実機で確かめられたのは Xbox 360（USB）だけ。One／Series の USB は通信方式（GIP）が別で、見え方も未確認（`Xbox-Input-Research.md` §3、§7） |
| 2 | 読み方 | HID の機器から、生のレポート（15 バイト）を直接読む（`IHidTransport` ＋ `IInputReportParser`）。XInput の API は使わない | XInput のスロット番号は VID/PID を含まず、複数の XInput 機器があると、どのスロットがどの機器かを決められない。HID の読み取りは、隠した状態でも、許可リストに登録したアプリなら可能と実機で確認済み（§7） |
| 3 | 隠し方 | **HID の子は、利用者が HidHide の GUI（`HidHideClient.exe`）で隠す**（今の DS4 と同じ使い方）。**USB の親（`XnaComposite`）は、DS4Windows がサービスの有効中に、その機器が接続されたとき、HID の子の親をたどって導出して隠し、サービスの停止時に、自分が足した分だけを解除する** | GUI は HID の子しか隠せず、それでは XInput の経路に漏れる（実測）。USB の親のパスは、シリアルを含み、抜き差しで変わらなかった。既存の `HidHideService`／`HidHideAPIDevice` を拡張するだけで済む。将来、HID の子も DS4Windows が登録する方式へ広げられる |
| 4 | 隠す対象の限定 | USB の親を隠すのは、Xbox 系（`XnaComposite`、VID_045E）の機器に限る | 一般の HID 機器で USB の親だけを隠すと、複合機器の全機能が消える（HidHide の公式の注意） |
| 5 | 解除の範囲 | DS4Windows が足した USB のパスを記録し、解除はその分だけ。利用者が自分で隠していたパスは触らない | 利用者の設定との衝突を避ける |
| 6 | 仮想パッドとの区別 | 既存の仮想パッドの検出（`CheckVirtualInfo` など）で、DS4Windows 自身が作る仮想の Xbox 360（同じ VID_045E／PID_028E）を、入力機器として拾わない | 仮想パッドを入力として拾うと、出力が自分に戻る（Step 19-1 で既存の判定を確認する） |

## 3. 段階

| 段階 | 内容 | 守り |
|---|---|---|
| 19-0 | 計画書の確認。レポートのデコード（全ボタン・スティック・トリガー・方向キーの対応）を、実機のレポートの記録から決める（調査用プログラムで、操作ごとの 15 バイトを記録する）。仮想パッドの区別（決定 6）の既存の判定を読む | 記録をテストの台本にする |
| 19-1 | `XboxReportParser`（`Input/Parsers`）。状態を持たず、15 バイトのレポートから `DS4State` を作る。差分テスト（台本の記録と期待値） | 解析器の単体テスト |
| 19-2 | `InputDeviceFamily`・`InputDeviceType` に値を足す（`[InputDeviceFamily]` つき）。`XboxProtocol`（`IDeviceProtocol`。電池は USB のため無し、出力は 19-5 まで無し）、`XboxDeviceCartridge`（`ProtocolDeviceCartridge` の派生。VID/PID の表）、接続フック（`NullInputDeviceModule` 相当）、`AddInputDevice<…>()` を 1 行。仮想パッドの除外（決定 6） | `ProtocolDeviceTests` の形の、偽の台本のテスト。層の検査 |
| 19-3 | 設定の定義（`ControllerSetting`）と、設定画面・はじめの起動画面（定義から自動生成）。最小の項目から始める | 保存の黄金テストが不変 |
| 19-4 | HidHide の拡張: (a) HID の子から、USB の親（`XnaComposite`）を導出する部品、(b) `HidHideAPIDevice` を使った、隠す機器の追加・解除、(c) サービスの有効中の接続時に隠す／停止時に、自分が足した分だけを解除、(d) 利用者の設定との衝突を避ける記録。偽の窓口（`IHidHideApi`）でのテスト | 既存の `HidHideService` のテストが不変 |
| 19-5 | 振動の出力（Xbox 360 の HID の出力レポート。調査して決める）。仮想パッドの振動の戻りを、物理コントローラーへ送る | 台本のテスト。ここで決められなければ、振動は次の Phase へ回す |
| 19-6 | 文書（モデル図 01・02、拡張の手順書、規則）、実機の確認の台帳 | |

## 4. 追加の調査（実施時に行う）

- 19-0: 全ボタンのデコード、Xbox 360 以外の同系統（Razer の Xbox 360 など、VID が違う機器）の扱い。
- 19-2: 仮想の Xbox 360 パッドの除外の方法（既存の検出に VID/PID のほかに何があるか）。
- 19-4: **隠しの反映のタイミング**（接続中に USB の親を足したとき、すぐ効くのか、抜き差しが要るのか）。要るなら、DS4Windows が機器の構成を作り直す方法（管理者権限が要る）を採るか、利用者への案内にするかを決める。HID の子のパスが抜き差しで変わる（`IG_nn`）点は、GUI で隠し直す運用になる（この計画書の範囲では自動化しない）。
- 19-5: Xbox 360 の振動の出力の形式。公開されている実装例を、GitHub で探して比べる（規則 4 章）。

## 5. リスク

- 実機の確認は、USB の Xbox 360 コントローラー 1 台だけ。Xbox One／Series、Bluetooth は対象外で、未確認のまま。
- HID の子のパスは、接続のたびに変わりうる。利用者が GUI でチェックし直す手間が残る（将来の改善候補: HID の子も DS4Windows が登録する）。
- 隠しの設定を変えたあと、反映に抜き差しが要る場合がある。
- 仮想の Xbox 360 パッドと、物理の Xbox 360 が同じ VID/PID。取り違えると、入力が自分に戻る。
