## 2. 対象の 6 項目と、調査の実測

### 項目 1: 「Unload on trigger release」で元のプロファイルに戻らない（Wave 1）
- 症状（総合検証 T-6、ログで確認）: プロファイル切替（一時プロファイル）の後、トリガーを離しても復帰しない。ログに `SpecialAction UNTRIGGER check` が出ない。
- 原因の連鎖（コードで確認）:
  1. 切替時、`Mapping`（`Mapping.cs` の Profile 分岐）が `deviceRuntime[device].UntriggerAction`（復帰の合図。復帰先の `prevProfileName`／`prevProfileWasTemporary` を含む）を保存する。
  2. 切替の適用処理 `ProfileApplicationService.CompleteProfileApplication` が `ActionManager.ClearDeviceState(device)` を呼ぶ。
  3. `DefaultActionManager.ClearDeviceState` が `Mapping.HandleDeviceDisconnect(device)` を呼び、これが `deviceRuntime[device] = new DeviceRuntimeState()` で、保存した `UntriggerAction` を消す。
  4. 離したとき、`UntriggerAction == null` のため、復帰の処理に入らない（`Mapping.cs` の `if (deviceRuntime[device].UntriggerAction != null)` を通らない）。
- 旧実装との比較（承認の根拠）:
  - 上流の元の実装（2019-04-23、`c168dabd`）: 復帰先を `UntriggerAction.prevProfileName` から読み、`ClearDeviceState` は呼ばない。復帰できていた。
  - 壊れた時期: `HandleDeviceDisconnect` の `deviceRuntime` の作り直し（`a892d372`、2025-12-18）と、適用時の `ClearDeviceState` の追加（`7d6b61e0`、2025-12-18）の組み合わせ。**DI 移行前のフォーク独自の追加**。Phase6 完了時点（`1c97977f`）も同じで、Phase7 の退行ではない。
  - さらに、復帰の経路が `RestoreFromAction`（`OlderProfilePath`＝最後に適用した「通常の」プロファイルへ戻す）に変わった（`d534655e`、2026-09-10）。上流は「切替の直前のプロファイル」（一時プロファイルだった場合は、それ）へ戻す。両者の差は、**一時プロファイルから一時プロファイルへ切り替えたとき**に出る（上流は前の一時プロファイルへ、現状は通常のプロファイルへ戻る）。
- 是正案（Q1・Q2）:
  - 案 A（推奨）: 適用処理が `ClearDeviceState` を呼ぶ前後で、`UntriggerAction`／`UntriggerIndex` を退避・復元する（`IMapping` に退避・復元のメソッドを追加）。復帰先は、上流と同じく `UntriggerAction.prevProfileName`／`prevProfileWasTemporary` を使う（`Mapping` の復帰処理が、`profileApplication.ApplyProfile(device, prevName, prevWasTemp, false, MappingAction)` を直接呼ぶ）。復帰の直前に `UntriggerAction = null` にして、復帰の適用がもう一度復元しないようにする。
  - 案 B: 退避・復元だけ（復帰先は現状の `OlderProfilePath` のまま）。差分は小さいが、一時 → 一時の切替で、上流と違う場所へ戻る。
  - 案 C: `HandleDeviceDisconnect` の呼び出しを、プロファイル適用の経路から外す。キー解放・キューのクリアも変わるため、影響が大きい。非推奨。
- 回帰テスト: `ProfileApplicationService`／`Mapping` の特性化テスト（切替 → 離す → 復帰、一時 → 一時、トリガーとは別の解除ボタン［`uTrigger`］、復帰後に再度切替できること、実際の切断では消えること）。

### 項目 5: ジャイロのマウススティックの水平軸が、1 台目のコントローラーの値で固定（K4-1。Wave 2）
- 症状: `Mouse.SixMouseStick`（`Mouse.cs` の `GetGyroMouseStickHorizontalAxis(0)`）が、引数 0 固定。2 台目以降も、1 台目のプロファイルの水平軸（ヨー／ロール）で動く。

- テスト: 2 台分の設定を変えた回帰テスト（軸の選択が台ごとになること）。

### 項目 2: L2／R2 のデッドゾーンの仕様変更の要望（Wave 6。設計から）
- 現行（`Mapping.SetCurveAndDeadzone`、上流 2019 年から同一）: デッドゾーン `dz` 以下は 0。超えたら、超えた点を 0% として、残りを 0〜100% に引き伸ばす（出力 = (入力 − dz)／(最大ゾーン × 255 − dz)）。その後、最大出力で頭打ち、アンチデッドゾーンで下駄を履かせる。
- 要望: 「デッドゾーン以下は 0、超えたら**押し込み量そのまま**を出力」（デッドゾーンを超えた瞬間に、80% に設定したなら 80% の出力が出る）。
- 影響範囲: 保存済みプロファイル（既存ユーザーの設定の感触が変わる）、アンチデッドゾーンとの関係（現行は「出力の開始値」。新方式では意味が変わる）、Controller Readings の表示（同じ関数を使うので追従する）。
- 是正案（Q7〜Q9）:
  - 案 A（推奨）: **モードを追加する**（`Scaled`＝現行、`Cutoff`＝新方式）。既定は `Scaled`（既存のプロファイルは変わらない）。L2／R2 ごとに選べる。XML には、既定でないときだけ要素を書く（既存のゴールデンファイルは変わらない）。画面には選択欄を追加する。
  - 案 B: 現行を新方式に置き換える。既存ユーザーの感触が変わる互換性の問題があるため非推奨。
- アンチデッドゾーンの扱い（Q8）: 推奨は、`Cutoff` モードでは**適用しない**（画面でも無効にする。値は保存されるが、モードを戻すと効く）。
- テスト: `SetCurveAndDeadzone` の特性化テスト（現行モードの出力を固定したうえで、新モードを追加）、XML の読み書き（既定は要素なし、新モードの往復）、ViewModel の連携。

## 8. 承認結果（2026-10-18）と確定内容

- 承認: Q1＝A、**Q2＝B**、Q3〜Q7＝A、**Q8＝B（内容を指定）**、Q9〜Q11＝A。
- **Q2＝B（復帰先は、現状どおり、常に通常のプロファイル）の反映**: Q1 の案 A のうち「復帰先を `prevProfileName` にする」部分は採用しない。W1 は、**退避・復元だけ**を行う。復帰先は `RestoreFromAction`（`OlderProfilePath`＝最後に適用した通常のプロファイル）のまま変えない。
  - 実装の注意: 復帰の適用も `ClearDeviceState` を呼び、退避・復元の対象になるため、`Mapping` の復帰の処理は、`ProfileSwitchAction.Stop` を呼ぶ**前に** `UntriggerAction` と `UntriggerIndex` を消す（消さないと、復帰の後に復元されて、毎フレーム復帰を繰り返す）。
- **Q8＝B（`Cutoff` モードの計算）の確定内容**:
  - 入力（物理値）が**デッドゾーン以下**なら、常に 0。
  - **デッドゾーンを超えたら**、「アンチデッドゾーンの設定値」と「ボタンの実際の％」の**大きい方**を出力する。ボタンの実際の％は、最大ゾーンを考慮した入力の割合（`Clamp(入力, 0, 255×最大ゾーン) ／ (255×最大ゾーン)`）とする。デッドゾーンで引き伸ばさない。
  - 最大出力（`maxOutput`）は、現行と同じ順序で、割合に頭打ちを掛け、そのあとアンチデッドゾーンとの大きい方を取る（アンチデッドゾーンが最大出力より大きい設定は、現行の `Scaled` と同様に、アンチデッドゾーンが優先される）。
  - 画面では、`Cutoff` でもアンチデッドゾーンの欄は有効のまま（Q8＝A の「無効にする」は採用しない）。
  - 式: `if (入力 <= dz) 出力 = 0 else { 割合 = Clamp(入力,0,最大)/最大; 割合 = min(割合, 最大出力); 出力 = max(割合, アンチデッドゾーン) }`。`dz` が 0 のときは、`Cutoff` でも入力が 0 より大きければ上の式を適用する（入力 0 は 0）。
  - 例: デッドゾーン 80%、アンチデッドゾーン 0% で、物理 79% は 0、81% は 81%。アンチデッドゾーン 90% なら、81% を超えた瞬間から 90% 以上になる。
- W6 のテストは、この式を固定する（境界: dz ちょうど、dz＋1、最大ゾーン、最大出力、アンチデッドゾーンが大きい／小さいとき）。
