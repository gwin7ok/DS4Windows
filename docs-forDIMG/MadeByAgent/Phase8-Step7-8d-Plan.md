## 1. 目的と範囲

Controls タブの「シフト」（`shiftTrigger` の副ボタンを押している間だけ、別の割り当てに切り替わる）を、統一エンジンへ載せる。7.8b（Key）と 7.8c（Macro）は、**シフトなし**の割り当てだけを扱った。7.8d は、シフトのある割り当てのうち、Key と Macro だけで構成されるものを扱う。運用は同じ（`MigratedControlKinds` の区分は、既存の Key・Macro のまま。シフトの有無は、割り当ての条件）。旧コードは Step8 まで残す。

**範囲（ボタン単位の所有。移行中の仕組み）**: 次をすべて満たす dcs だけを新経路が処理する。

- 通常の割り当てが、Key か Macro。または、未設定（Default）で、そのボタンが**スティックの方向・ジャイロ・スワイプではない**（ボタン、タッチ、L2／R2。理由は §2.3）。
- シフトの割り当て（`shiftActionType`）が、Key か Macro（Default でない）。
- Extras が空（通常・シフトとも）、Lightbar マクロが有効でない。

**やらないこと**: シフトに Button（X360・マウス・ホイール）を割り当てたもの（7.8f）、Extras（7.8e）、通常が Default のスティックの方向・ジャイロ・スワイプ（7.8f）、旧コードの削除（Step8）。

## 2. 現状の調査（2026-10-20）

### 2.1 旧経路のシフト（`ProcessControlSettingAction`）

1. **シフトの成立**: `dcs.shiftActionType != Default` かつ `ShiftTrigger(dcs.shiftTrigger)`。`ShiftTrigger` は、`shiftTrigger` の番号から副ボタンを `shiftTriggerMapping`（35 要素）で引き、`GetBoolMapping`（スティックは ±55、L2／R2 は 100 超、**ジャイロは 0 超**）で判定する。番号 0 は「なし」（常に偽）。**番号 26 は特別で、`cState.Touch1Finger`（タッチパッドに指 1 本）**。
2. **割り当ての選択**: シフトが成立していれば、シフトの割り当て（`shiftAction`、`shiftKeyType`）、そうでなく通常が Default でなければ、通常の割り当て。
3. 選ばれた割り当ての実行（Key／Macro／Button）と、そのあとの `ResetToDefaultValue`（割り当てたボタンの通常の出力を消す）は、**通常のときと同じコード**。
4. 通常が Default で、シフトが成立していないときは、Default の分岐（スティックの方向だけ `customMapQueue` に素通しを積む）。ほかの Default のボタンは何もしない（元の出力がそのまま出る）。

### 2.2 旧経路の切り替わりの癖（W1 で実測する）

旧経路の Key は、押下・解放のエッジを、**名前（`Synthetic_Key_{device}_{control}`）で**検出する。通常とシフトは、同じ名前（トグルと ScanCode の指定が同じなら、同じ合成 SA）なので、**押したままシフトの副ボタンを押す・離すと、押下・解放のエッジが起きず、通常のキーが押されたまま、シフトのキーは押されない**可能性がある（離すときは、そのときの割り当てのキーで解放を送るため、押したキーが残る可能性）。Macro も、`macrodone` の扱いが絡む。W1 で、旧経路の実測値を固定する。

### 2.3 新経路の設計に効く点

- **ボタンごとの束縛が 2 つ（通常とシフト）要る**。7.8b・7.8c のエンジンは、ボタン → 束縛の表が 1 対 1 だった。2 つ持てるようにする（§3.2）。
- **通常が Default の場合**: シフトが成立していない間は、旧経路は何もしない（元の出力を消さない）。新経路で「毎フレーム消す」方針（`ErasesOutputEveryFrame`）をシフトの束縛に使うと、シフトが成立していない間の元の出力まで消えてしまう。**ボタン・タッチ・L2／R2**は、押下 ＝ 出力が出ている状態なので、「成立中だけ消す」（`ResetsTriggerOutput`）で、旧経路と同じ結果になる。**スティックの方向・ジャイロ・スワイプ**は、押下の判定と出力の値が一致しない（旧経路は、押していなくても、傾きがあれば出力が残る）ため、7.8f（Default の扱い）まで旧経路に残す。
- **シフトの判定のジャイロの閾値**: `GetBoolMapping`（0 超）と、SA のトリガーの判定（±67）が違う。シフトの副ボタンにジャイロを選ぶ使い方は稀（Q4）。
- 7.8c で、Controls の Macro の押下の判定を SA の判定に合わせたため、**Key と Macro で、主ボタンの判定の種類が違う**（Key は Assignment、Macro は Trigger）。組み合わせ（通常が Key、シフトが Macro など）でも、束縛ごとに、その割り当ての種類の判定を使う。

## 3. 設計

### 3.1 層の割り振り

| 層 | 担当 |
|---|---|
| 入力監視層 | `TriggerInput`（押下状態。`IsActive`、`IsControlActive`、タッチ 1 本指を足す） |
| 信号変換層 | `ControlBindingBuilder`（dcs → 通常・シフトの 2 つの束縛。シフトの副ボタンの解決）、`ControlShiftInputAction`（主ボタン ＋ シフトの条件）、エンジン |
| 出力層 | 既存の `KeyOutputAction`／`MacroAction`（変更なし） |

### 3.2 追加・変更するもの

- **シフトの副ボタンの表（`ShiftTriggers`。新設。`Actions/`）**: `Mapping.shiftTriggerMapping`（35 要素）と、番号 26（タッチ 1 本指）を、変換層が使える形で持つ。`Mapping` の元の表は Step8 まで残し、一致をテストで保証する。
- **`IControlTriggerInput` の拡張**: `bool IsOneFingerTouching()`（旧 `cState.Touch1Finger`）。`TriggerInput` が実装する。
- **`ControlShiftInputAction : IInputAction`（新設。Q2＝A）**: 主ボタンの成立（割り当ての種類の判定。`ControlJudgement`）と、シフトの状態（副ボタンの判定）を合わせて評価する。**通常の束縛は「主ボタンが成立 ＋ シフトが成立していない」、シフトの束縛は「主ボタンが成立 ＋ シフトが成立」**。2 つの条件が互いに排他なので、`ExclusionGroup` は使わない（設計書 §3.3 の案からの変更。理由: 条件で決まるため、エンジンの順序に依存せず、決定的）。シフトが成立しているかは、旧経路と同じく、`shiftActionType != Default` かつ副ボタンの判定。
- **`ControlBindingBuilder`（拡張）**: §1 の条件を満たす dcs ごとに、シフトの束縛（と、通常が Key／Macro のときは、通常の束縛）を作る。識別用の SA は、通常は 7.8b・7.8c と同じ名前、シフトは `Synthetic_KeyShift_{device}_{control}`／`Synthetic_MacroShift_{device}_{control}`（状態は別）。シフトの束縛の方針: Key は `respectsFreshPressGuard: false`、Macro は `true`（SA と同じ）。通常が Default のとき、シフトの束縛は `erasesOutputEveryFrame: false`、`resetsTriggerOutput: true`（成立中だけ消す。§2.3）。通常が Key／Macro のとき、両方 `erasesOutputEveryFrame: true`（旧経路は、どちらの割り当てでも毎フレーム消す）。
- **エンジン**: ボタン → 束縛の表を、1 ボタンあたり最大 2 つ（通常・シフト）にする。`OwnsControl` は、どちらかがあれば真。`ProcessControl` は、**前フレームで実行中の束縛（`BeingTriggered`）を先に処理**してから、ほかを処理する（シフトの切り替わりで、押されていたキーの解放を、新しいキーの押下より先に行うため）。
- **`ControlBindingKind`**: 変更なし（区分は Key・Macro のまま）。所有の判定は、束縛の区分の移行のスイッチで行う（シフトの束縛が Key なら Key の区分、Macro なら Macro の区分）。

### 3.3 動作の維持と、変わる可能性のある点（W1 の実測のあと、確定して承認を得る）

- 維持: シフトの選択の規則（`shiftActionType` が Default なら通常のまま。副ボタンの番号 0 は「なし」）、副ボタンの番号表、番号 26（タッチ 1 本指）、通常とシフトの割り当ての実行（7.8b・7.8c の動作）。
- **変わる可能性**: (1) 押したままのシフトの切り替えで、旧経路は押下・解放のエッジが起きない可能性（§2.2）。新経路は、通常の割り当ての解放と、シフトの割り当ての押下を、切り替えのたびに行う（押されたままのキーが残らない）。(2) シフトの副ボタンのジャイロの閾値（Q4）。(3) Macro のシフトは、SA の仕様（立ち上がりで 1 回。Fresh-press ガード）になる（7.8c の承認済みの変更の範囲）。

## 6. 質問

- **Q1（範囲）**: A（推奨）: §1 のとおり（通常が Key／Macro／Default［スティック・ジャイロ・スワイプ以外］ × シフトが Key／Macro。Extras なし）。他は旧経路。B: 通常が Key／Macro の組み合わせだけ（Default の通常を 7.8f に回す。範囲は小さいが、最もよく使われる「Default ＋ シフト」が旧経路に残る）。
- **Q2（シフトの排他の方法）**: A（推奨）: 束縛の入力に、シフトの条件を含める（通常は「シフトなし」、シフトは「シフトあり」。互いに排他なので `ExclusionGroup` は使わない）。B: `ExclusionGroup` を使う（設計書 §3.3 の案。エンジンの処理順に依存する）。
- **Q3（押したままの切り替わり）**: A（推奨）: 切り替わりのたびに、通常の割り当ての解放と、シフトの割り当ての押下を行う（キーが残らない）。W1 の実測で、旧経路が違う動きなら、不具合の修正として承認する。B: 旧経路の挙動を再現する（実測の結果次第。再現が困難なら相談）。
- **Q4（シフトの副ボタンの判定）**: A（推奨）: SA のトリガーの判定（`IsActive`。ジャイロは ±67）に合わせる。旧経路は 0 超で、ジャイロの副ボタンの閾値だけ変わる（稀な使い方）。B: 旧経路の判定（`GetBoolMapping`）を、シフト専用に再現する（判定の種類が 3 つに戻る）。
- **Q5（タッチ 1 本指）**: A（推奨）: `IControlTriggerInput` に `IsOneFingerTouching` を足す。B: 番号 26 のシフトは、旧経路に残す。
- **Q6（Default ＋ シフトの消去）**: A（推奨）: 成立中だけ消す（`ResetsTriggerOutput`）。ボタン・タッチ・L2／R2 に限る（§2.3）。B: 通常が Default のシフトは、7.8f に回す（Q1 の B と同じ）。
