## 見つかった不具合（16 の確認中に、利用者が報告。いずれも RV21 で修正）
1. **言語を切り替えて「適用」を押すとクラッシュ**: `FallbackValue={lex:Loc …}`（AssignmentEditor 5 か所・BindingWindow 1 か所）を、言語の切替で WPFLocalizeExtension が使用済みの Binding へ書き込もうとして `InvalidOperationException`。→ `FallbackValue` の `lex:Loc` を外した（結びつけ先は DataContext が生成時に設定される）。ガードテスト `XamlBindingPitfallGuardTests`。
2. **日本語モードで、Press Key の「切り替えモード」の選択が表示されない**: `SelectedValuePath="Content"` が、翻訳された文字（押す／切り替え）と、VM の値（Press／Toggle）を比べていた。→ `Tag="Press"`／`Tag="Toggle"` ＋ `SelectedValuePath="Tag"`。
3. **Controls タブの割り当て一覧の行をダブルクリックしても割り当て編集が開かない**（RV4-3a で `MouseDoubleClick` ハンドラーを `InputBindings` の `MouseBinding` へ移したときの不具合）: `InputBinding` は視覚木の外にあり、`RelativeSource AncestorType` が解決できない。→ code-behind でコマンドの実体を直接結ぶ。同じ形のログ一覧（`MainWindow`）のダブルクリックも直した。ガードテスト `XamlBindingPitfallGuardTests`。

### 修正の再確認（利用者）
- ①（言語の適用）・②（日本語の切り替えモード）: **OK**。
- ③（ダブルクリック）: **NG のまま**（`InputBindings` の `MouseBinding` に替えた修正では直らなかった）。原因: 一覧の項目（`ListViewItem`）が `MouseDown` を処理済みにするため、一覧に付けた `MouseBinding` に届かない。→ `MouseDoubleClick` イベントで結び直した（割り当て一覧・ログ一覧・プロファイル一覧）。再確認待ち。

4. **割り当て編集画面で、種別の一覧を変えても、下の設定の部品（タブ）が切り替わらない**（Controls・SA の両方。利用者が確認 21 の途中で報告）: `ActionTypeIndex` が変更通知を出さず、一覧とタブが同じ値に結ぶ 2 つの結びつけの同期が取れなかった。VM が `INotifyPropertyChanged` を実装していない間は、WPF が `PropertyDescriptor` 経由で同期していたが、`ObservableObject` への付け替え（RV7）で、通知のないプロパティは同期されなくなった。→ `SetProperty` で通知する。再現のテスト `AssignmentEditorTabSyncTests`（実際の画面を開き、一覧の選択とタブの選択を比べる）。**同じ形（`ObservableObject` の VM の、通知のない書き込み可能なプロパティを、複数の部品が結ぶ）が、ほかにないかを、確認の続きで注意して見る**。

### 確認 21 で見つかった不具合（4 と同じ原因。「設定した直後に画面へ出ない」）
- プログラム起動: 参照で .exe を選んでも、選んだプログラムが表示されない（保存して開き直すと表示される）。
- 複数動作: マクロを記録しても、ボタンが「記録しました」にならない（保存し直すとなる）。
- BT 切断: 長押し時間の既定値が 0 ではなく空欄（テストでは新規の画面で 0.00 と表示され、再現しなかった。通知の修正で直る可能性があり、実機で再確認する）。
- **原因**: `ObservableObject`（INPC）に付け替えた ViewModel は、WPF が旧来の `XxxChanged` イベントの通知を見なくなる（RV7）。`CompositeDeviceModel`・`LaunchProgramViewModel`・`MultiActButtonViewModel`・`PressKeyViewModel`・`CheckBatteryViewModel`・`LoadProfileViewModel`・`RecordBoxViewModel`・`SpecialActionsListViewModel`・`LanguagePackViewModel`・`MainWindowsViewModel` の `XxxChanged` を呼ぶ 22 か所が、`PropertyChanged` を出していなかった。
- **修正**: (1) 該当の 22 か所に `OnPropertyChanged(nameof(Xxx))` を足した（`ProgramIconPath` も）。(2) 通知のない単純なプロパティ（`{ get => x; set => x = value; }`）を `SetProperty` にした。(3) スペシャルアクションの各 ViewModel の `LoadAction`／`LoadControlItem` の終わりで、全プロパティを通知する。テスト `ViewModelChangeNotificationTests`。
- 同種の調査: `public event EventHandler XxxChanged` を持つ全クラスを走査し、INPC を実装しているのは上の ViewModel だけだった（INPC でないクラスは、旧来の通知が今も使われる）。

### 機能廃止の依頼（確認 26 の途中）
- 2026-11-21 利用者の明示的な指示: タッチパッド出力モード「マウススティック」（`TouchpadOutMode.MouseJoystick`）を削除する（規約 2.2 の例外に該当。範囲・既存プロファイルの扱いは別途確認してから実施）。
- **実施（コミット済み）**: タッチパッド・ジャイロの出力モード「マウススティック」の画面・出力の処理を削除。列挙値 `MouseJoystick` と設定の保存・読み込みは、プロファイル XML の形のために残した（型に TODO を記載）。古いプロファイルは、「操作」モードの既定値として読む（そのスロットのタッチパッド／ジャイロの設定は、すべて既定値へ戻す）。
- ジャイロのマウススティックを使う既定のプリセット「ゲームパッド＋ジャイロカメラ」（通常・DS4 型の 2 種）も削除（利用者の承認）。
- 出力モードの選択番号は、パススルーが 3 → 2 に繰り上がる（保存は名前のため影響なし）。
- 実機で確認すること: (1) タッチパッド・ジャイロの出力モードの一覧に「マウススティック」がない、(2) 古いプロファイルを開いて、操作モードで開く、(3) プリセットの一覧にジャイロカメラがない。

## 確認31 A: 自動プロファイル「プログラムを追加」のメニュー（NG → 修正）
- 症状: 4 つのメニュー項目（Steam・スタートメニュー・フォルダー・exe）を選んでも何も起きない。
- 原因: ボタンの Click からコードで `ContextMenu.IsOpen = true` にしており、右クリックと違って PlacementTarget が入らず、メニューが DataContext を継承しない。`Command="{Binding …}"` が解決されなかった（RV3-5 の Click→Command 化で顕在化）。
- 修正: `AutoProfiles.xaml.cs` で、開く前に PlacementTarget と DataContext を明示。`AutoProfilesAddMenuTests` を追加（修正前は 0 件、修正後は 4 件が結ばれる）。
- 再確認（修正後）: A OK（4 項目とも動いた）。
- B OK（検査中は無効、一覧が埋まる、追加後のメニューの出入り）。C OK（選択なしで (none)）。確認31 完了。

## 確認36（タッチパッド）
- 押し込みのクリックは、Controls タブのタッチ 4 エリアが「既定」のときだけ出る仕様（Unbound では出ない）。
- 複数指の押し込み→右クリックが、マウスモードだけ一瞬で離される（他のモードは押している間保持）。RV13 より前から同じ処理のため、今回の変更による劣化ではない。原因は未特定で、KI-24 に記録した。他の項目は正常。
- 追記: 同日の再操作では、複数指の押し込みの右クリックも正常に動いた（再現せず）。KI-24 は「再現したら再開」とする。
