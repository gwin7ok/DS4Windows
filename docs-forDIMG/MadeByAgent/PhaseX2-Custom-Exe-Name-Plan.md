## 1. 目的
設定画面の「カスタム実行ファイル名」（`fakeExeNameTxt`）は、プロセス名で DS4Windows を検出して入力を無視するゲームへの対策として、`DS4Windows.exe` を別の名前で使えるようにする機能である。現在は、複製を作るところまでしか正しく動かず、更新との連動が切れている。これを、利用者が意識せずに使える形へ立て直す。

### 2.1 フォーク時点の動き（本体と DS4Updater の組）
| 段階 | 動き |
|---|---|
| 設定したとき（本体） | `DS4Windows.exe` を `名前.exe` として複製し、前の名前の複製を消す |
| 設定の保存（本体） | 本体のフォルダーの `custom_exe_name.txt` に名前を書く |
| 更新の開始（本体） | 同じフォルダーの `DS4Updater.exe` を、`--launchExe <いま動いている exe の名前>` を付けて起動する |
| 更新の完了（DS4Updater） | 自分のフォルダーの `custom_exe_name.txt` を読み、新しい `DS4Windows.exe` と設定ファイル 2 つを、その名前で複製し直す |
| 再起動（DS4Updater） | `--launchExe` で受けた名前の exe を起動する |

要点は、DS4Updater が本体と同じフォルダーにあり、「自分のフォルダーの `custom_exe_name.txt`」が本体の書いたファイルと一致していたこと。本体が自分で複製へ切り替える処理は、当時からない（複製から起動するのは利用者の操作）。

## 3. 現状（調査）
### 3.1 本体の動き
- 入力欄からフォーカスが外れると、(1) ファイル名に使えない文字を含む値を黙って捨てる（`Core/Settings/AppSettingsService.cs:654`）、(2) 前の名前の `名前.exe`／`.runtimeconfig.json`／`.deps.json` を消す、(3) `DS4Windows.exe` と設定ファイル 2 つを新しい名前で複製する（`UI/ViewModels/SettingsViewModel.cs:357`、`545`、`658`）。
- 設定の保存のとき、本体のフォルダーの `custom_exe_name.txt` へ名前を書く（`Core/Persistence/AppSettingsXmlSerializer.cs:490`。読み込みは同 `417`）。`Profiles.xml` には入らない。
- **この設定を読む処理は、上のほかにない**。起動、自動起動の登録、更新、HidHide の登録は、設定された名前を見ない。
- 複製から起動した場合、「動いている自分のパス」（`IPathService.ExecutablePath`）を使う処理が、自然に複製を指す: スタートアップの登録（`SettingsViewModel.cs:470`・`476`・`598`）、HidHide への登録（`Output/Services/HidHideService.cs:51`）、更新後の再起動の先（`UI/UpdaterWindow.xaml.cs:102`・`242`・`292`、`Core/Updater/UpdaterLaunchArguments.cs:18`）、管理者での再起動（`UI/MainWindow.xaml.cs:1330`、`Processing/Services/DeviceRegistryHooks.cs:82`、`UI/ViewModels/MainWindowsViewModel.cs:63`）、通知の登録（`UI/Services/AppNotificationRegistration.cs:42`）。
- 単一起動の判定は、名前つきのイベントで行う（`Composition/Startup/SingleInstanceGuard.cs:25`）。`DS4Windows.exe` と複製は同時に起動できない。
- 本体は、更新プログラムを起動したあとも動き続け、終了を更新プログラムに任せる（`UI/UpdaterWindow.xaml.cs:111`）。

### 3.2 更新プログラム（DS4Updater v3.0.0）の動き
- 複製を作り直す処理は残っている（`Updater2/MainWindow.xaml.cs:950`〜`975`）。ただし、`custom_exe_name.txt` を **自分のフォルダー**（`ds4UpdaterDir`。現在は `DS4Windows\DS4Updater\`）で探す（同 `286`、`951`）。
- 動作中の本体を、プロセス名 `DS4Windows` だけで探し、見つかれば終了させて待つ（同 `635`、`678`）。
- 再起動は、`--launchExe` で受けたパスの exe で行う（`Updater2/App.xaml.cs:78`〜`88`、`224`）。フルパスも受け付ける。

## 5. 方式の案と比較

### 案 A: DS4Updater と連動させる（元の設計へ戻す）
- A1: DS4Updater が、`custom_exe_name.txt` を本体のフォルダー（`ds4WindowsDir`）で探す（`Updater2/MainWindow.xaml.cs:286`、`951`）。
- A2: DS4Updater が、動作中の本体を、`DS4Windows` に加えて、カスタム名と `--launchExe` の名前でも探す（同 `635`、`678`）。本体からカスタム名を引数で渡す形にすれば、ファイルの場所に頼らない。
- 本体の変更は、引数を足す場合だけ。

### 案 B: 本体だけで、複製を最新に保つ
- 起動時に 1 回、複製が `DS4Windows.exe` と違えば作り直す（大きさと更新日時で比べる）。
- `DS4Windows.exe` から起動したときは作り直せる。**複製から起動したときは、動いている自分自身を上書きできない**（名前を変えてから置く方法はあるが、込み入る）。
- P2（更新中の検出）は、この案では直せない。

### 案 C: 起動役の方式（2026-11-12 のユーザーの提案）
- 起動は、毎回 `DS4Windows.exe` で行う。
- 機能の有効／無効の設定を新しく設ける。有効なら、`DS4Windows.exe` が、複製が古ければ作り直し、複製を同じ引数で起動して、自分は終了する（`DS4Windows.exe` は「起動役」になる）。
- 更新は、`DS4Windows.exe` の側で行う。やり方は 2 つ。
  - C-u1（推奨）: 複製として動いている本体が、更新プログラムを起動した直後に、自分で終了する。更新プログラムには、再起動の先として `DS4Windows.exe` を渡す。更新プログラムはダウンロードのあとにファイルを置き換えるので、その時点で本体は終了済みになる。更新プログラムを変えずに済む。
  - C-u2: 複製が `DS4Windows.exe` を「更新用」の引数で起動して終了し、`DS4Windows.exe` が更新プログラムを起動する。引数と、前のプロセスの終了待ちが増える。
- 更新のあとは、更新プログラムが `DS4Windows.exe` を起動し、起動役が複製を作り直してから複製で起動する。

## 8. テストと確認の方針
- 判断と手順は、ファイル操作・プロセスの起動・単一起動の印を偽物にして、単体テストで守る（規約 4 章「OS の状態に触れない」）。
- 実機で確かめる項目（案 C の場合）:
  1. 有効にして `DS4Windows.exe` から起動し、動作中のプロセス名が複製の名前だけになること。
  2. 2 回目の起動（`DS4Windows.exe` から）で、動作中の複製の画面が前面に出ること。
  3. コマンドラインの `-command`（動作中の本体への指示と問い合わせ）が、従来どおり動くこと。
  4. 最小化起動（`-m`）、スタートアップ（Program と Task の両方）。**Task の場合、起動役が終了しても複製が動き続けること、管理者の権限が引き継がれること。**
  5. 更新: 複製として動いている状態から更新し、更新のあと、複製が新しくなって、複製で起動すること。更新を取りやめた場合の動き（D3）。
  6. HidHide: 複製の名前で、隠したコントローラーが見えること。
  7. 通知（トースト）が、複製の名前で動いているときも出ること。
  8. 無効に戻したとき、`DS4Windows.exe` のまま動き、複製が残っても害がないこと。
- 実機で確かめる項目（案 A の場合）: 複製から起動したまま更新して、本体が終了され、更新が完了し、複製が作り直され、複製で再起動すること。

| V3 | 古い複製の `exe` で、新しい `DS4Windows.dll` が起動できること | P1 の実害の大きさ（案 B・C の必要性）の裏づけ |

| V5 | タスク スケジューラーから起動した `DS4Windows.exe` が終了したあと、子のプロセスが動き続けるか | 案 C の成否に関わる |
| V6 | 元の DS4Updater（schmaldeo 側）の、プロセスの検出の当時の実装 | P2 が元からかどうか（経緯の記録のため） |

## 10. リスク
- 案 C は、起動の入口と、更新・スタートアップの登録に触れる。起動の順序は `StartupOrderGuardTests`、開始・停止の安全弁は `LifecycleGuardTests` が守っている。順序を変えるのは、起動役の判断を先頭に足すことだけにする。
- 「自分を別名で複製して起動し、自分は終了する」動きは、セキュリティソフトに疑われやすい。機能が有効なときだけ行い、複製は違うときだけ作る。
- 案 A は、別リポジトリの公開と、利用者の手元の更新プログラムの版に依存する。
- 既存の利用者の動き（複製を手で起動する）を変えない既定にする（No Feature Drop。D4・D7）。
