KI-14 は、説明文だけ直して閉じるのではなく、**PhaseX4 として計画だけ起票し、あとで本格的に直す**。

## 2. 問題の要約（詳細は X2 の §4）
| ID | 重さ | 内容 |
|---|---|---|
| P1 | 中 | 更新のあと、複製が作り直されない見込み（本体は本体のフォルダーへ `custom_exe_name.txt` を書き、DS4Updater はサブフォルダーで探す） |
| P2 | 高 | 複製から起動したまま更新すると失敗する見込み（DS4Updater が `DS4Windows` のプロセス名しか探さない） |
| P3 | 低 | 説明文（`CustomExeNameInfo`）が、実態と合わない |
| P4 | 低 | 使えない文字を入れると、値は捨てられるのに、前の複製だけが消える |
| P5 | 低 | 拡張子つきで入れると `名前.exe.exe` ができる |
| P6 | 低 | 複製した設定ファイル 2 つは、おそらく使われない |
| P7 | 低 | 書き込めないフォルダーでの複製の失敗が、利用者に見えない |
| P8 | 中 | 利用者が、複製を自分で探して起動する必要がある（案内がない） |

調査は、ソースの読み取りだけで、実機での再現は未確認（X2 の V1〜V6 で裏取りする）。

## 3. 方式の候補（詳細は X2 の §5）
- 案 A: DS4Updater と連動させる（`custom_exe_name.txt` を本体のフォルダーで探し、動作中の本体の検出にカスタム名を加える）。変更は DS4Updater 側が中心。
- 案 B: 本体だけで、複製を最新に保つ（単独の採用は非推奨。P2 が残る）。
- 案 C: 起動役の方式（`DS4Windows.exe` が、複製を作り直して起動し、自分は終了する。更新は C-u1＝複製が自分で終了、または C-u2＝引き継ぎ）。本体だけで P1・P2・P8 を直せるが、動作の変更が大きい。
- 2026-11-12 時点の見立て: 候補は「案 C（C-u1）」または「案 A（A1＋A2）」。**実装の前に、X2 の §6（D1〜D9）を、その時点のコードで確かめ直して決める**。

## 4. 着手のときの手順
1. X2 の §9 の V1〜V6 を裏取りする（特に V1: 複製から起動して更新し、P2 が実際に起きるか）。
2. X2 の §6 の D1〜D9 を、選択式でユーザーに確認して決める。
3. 採った方式の分だけを、個別計画書（`PhaseX4-StepY-Plan.md`）にする（X2 の §7 の Step 案が下敷き）。
4. 共通の小さな是正（X2-1〜X2-3: P4・P5・P3）は、方式に依らず先に行える。
5. 実機確認は、X2 の §8 の項目を、1 件ずつ選択式で行う。

## 5. 守ること
- 既存の利用者の動き（複製を手で起動する）は、既定では変えない（No Feature Drop。D4・D7）。
- 機能の廃止になる選択（D1 の「廃止する」）は、ユーザーの明示的な承認を得てから行う（規約 2.2）。
- 新しい利用者向けの文言・ログは、`Strings.resx`／`Strings.ja.resx` のキーで書く（規約 2.3）。
