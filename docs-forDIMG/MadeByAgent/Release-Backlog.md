## 2. 現状の調査（2026-10-23）

- **R-1**: SA の一覧は `SpecialActionsListViewModel`（追加・削除・読み込み・保存は `ISpecialActionRepository`）。複製は、既存の `SpecialAction` を、新しい ID（`id`）と重複しない名前でコピーして保存するだけでよく、エンジン側の変更は不要。
- **R-2**: 再生オプションは `MacroPlaybackOptions`（Play Once／Repeat While Held）。保存は `DS4KeyType.RepeatMacro` と `ScanCode` のフラグで表す（Controls の `RecordBox` と SA の Macro タブが共通）。トグルの繰り返しには、新しい保存フラグ（古い版との互換に注意）と、実行側の状態（トグルのオン・オフ。`ActionInstanceState.IsToggledOn` に相当）が要る。
- **R-3**: マクロの値は、整数のコード（0〜255＝キー、256〜260＝マウスボタン、それ以外＝待ち時間）で表す（`MacroStepExecutor`）。マウスの移動を入れるには、新しいコード体系（移動先の座標を持つ。1 つの整数に収まらない）と、記録画面（`RecordBox`）の表示・編集、保存形式（`Macro` の文字列）の拡張が要る。
- **R-4**: 前面のウィンドウを取得する処理は `DefaultProcessInspector`（`GetForegroundWindow`）にあるが、前面へ出す処理（`SetForegroundWindow`）はない。新しい種別（`ActionTypeId`）、編集画面（`LaunchProgram` に近い）、保存、実行（Windows の前面化の制限への対応が要る）が必要。
- **R-5**: SA のトリガーは、`TriggerInput` で、閾値による真偽（トリガーは 100 超、スティックの軸は中心からの幅、ジャイロは 67 超）にしている。SA のアナログ出力は、固定の強さ（`analogStrength`）で出す。「閾値なし」への変更は、スティックのわずかな傾きでも成立する可能性があり（デッドゾーンの後の値で判定するかどうかの確認が要る）、③のアナログの値の受け渡しは、`ButtonOutputAction` の仕組みの拡張が要る。
- **R-6**: `DS4Forms` のコードと XAML に、マウスホイールの独自処理（`PreviewMouseWheel`／`OnMouseWheel`）は見つからなかった。WPF の標準の挙動（ScrollViewer は、Windows の「スクロールする行数」に従う。ただし、ComboBox、Slider、NumericUpDown など、ホイールで値が変わる部品では、ホイールがスクロールにならない）の可能性がある。現象を確認してから、直し方を決める。

### 推奨するリリースまでの順序

1. **K7b-1 の様子見**（3 日。並行）。
2. **R-1（SA の複製）** → **R-6（ホイール）**: 小さく、リスクが低い。リリース前に行う。
3. **R-5 の仕様の確定**（①②③の判断、デッドゾーンとの関係、既存プロファイルへの影響）: 実装の前に、ユーザーと詰める。①②だけを先に実装するか、全体を後に回すかを決める。
4. **R-2・R-3・R-4**: リリース後（次の版）。順序の案は R-2（保存形式の追加が小さい）→ R-4 → R-3。
5. 未確認の実機確認（P9M3-3 ほか）は、リリース前に消化する。

### 確認したい点

- R-6: どの画面で、どのような現象か（例: スクロールの量が、Windows の設定と違う、非アクティブなウィンドウの上でスクロールできない、ComboBox の上のホイールで値が変わってしまう、など）。
- R-5: 「閾値なし」は、トリガーなら押し込み量が 0 より大きい、スティックなら中心から少しでも傾いた、という意味か。デッドゾーンの後の値で判定するか。
